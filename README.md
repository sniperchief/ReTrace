# ReTrace

*Every repair should leave a history.*

ReTrace helps independent generator technicians record each repair and look up a generator's history when it comes back.

| Path | What |
|---|---|
| [`web/`](web/) | Next.js app (TypeScript, Tailwind CSS, MongoDB) |
| [`docs/technical-spec.md`](docs/technical-spec.md) | Architecture, data model, decisions |
| [`docs/setup.md`](docs/setup.md) | Local setup, MongoDB Atlas, tests |
| [`docs/deploy.md`](docs/deploy.md) | Deploying to Railway (AI service) and Vercel (website) |

## Status

- **Phase 1:** accounts, customers, generators, and manual repair records with per-generator history.
- **Model update:** Gemma 3 1B (~0.8 GB) replaces Gemma 4 E2B, and a rule-based extractor fills the form alongside it, or on its own when the AI is unavailable. See [docs/technical-spec.md §13](docs/technical-spec.md).
- **Phase 3:**
  - Repair search by words, part and date range, across a technician's confirmed repairs. Matching is keyword (word-prefix), not semantic.
  - A timeline on each generator page.
  - A summary of the recorded history, generated by code (not AI), that links to its source records.
  - See [docs/technical-spec.md §12](docs/technical-spec.md).
- **Phase 2:** voice notes or typed notes are transcribed (Whisper) and turned into a draft (Gemma). The technician reviews and confirms each draft before it becomes a repair. This is optional (`INFERENCE_MODE`); manual entry always works.
  - [`inference/`](inference/): the self-hosted model service.
  - [`docs/inference-benchmark.md`](docs/inference-benchmark.md): measured speed and accuracy.

## Quick start

```bash
cd web
npm install
cp .env.example .env.local   # then fill in MONGODB_URI and AUTH_SECRET
npm run db:indexes
npm run dev
```
